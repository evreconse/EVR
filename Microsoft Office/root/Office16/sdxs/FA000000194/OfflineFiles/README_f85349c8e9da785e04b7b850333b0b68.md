# Vendored `@1js/web-previewer`

This folder contains a checked-in copy of the built `@1js/web-previewer` artifacts.

## Why vendored

We self-host `@1js/web-previewer` at `fa000000194.resources.office.net` (the SDX origin) instead of loading it from Loop's CDN (`loop.usercontent.microsoft`). This is the workaround for the "Trying to reconnect" toast that XLO shows when the previewer is loaded cross-origin into the SDX iframe. Full investigation in `C:\Users\vipulg\.copilot\skills\excel-agent-dashboards\SKILL.md` §17 and §18.

## How it gets served

`webpack.config.common.js` has a `CopyWebpackPlugin` pattern that copies this folder into `dist/en-us_web/web-previewer/` on every build. The SDX dev server then serves it at:

```
https://fa000000194.resources.office.net/web-previewer/index.html
```

Runtime URL resolution lives in `src/dashboardViewer/previewerConfig.ts`.

## How to refresh / update

The bundle was built from `@1js/web-previewer` in the 1JS midgard monorepo. To rebuild and re-vendor:

1. In a 1JS midgard codespace:
   ```bash
   cd /workspaces/1JS/midgard
   yarn fast @1js/web-previewer
   cd packages/web-previewer
   yarn build
   ```
2. Output appears in `packages/web-previewer/dist-automation/` (~94 MB with source maps).
3. Tar only the runtime files (skip `.js.map`, skip other-tenant HTML entries):
   ```bash
   cd dist-automation
   mkdir -p /tmp/wp-runtime
   cp *.js *.LICENSE.txt index.html *.webp /tmp/wp-runtime/
   tar czf /tmp/wp-runtime.tar.gz -C /tmp/wp-runtime .
   ```
4. Download to this folder and extract:
   ```powershell
   gh codespace cp -e -c <codespace-id> "remote:/tmp/wp-runtime.tar.gz" "$env:TEMP\wp-runtime.tar.gz"
   Remove-Item .\* -Recurse -Force
   tar -xzf "$env:TEMP\wp-runtime.tar.gz" -C .
   ```
5. Patch `index.html` to compute the script base URL at runtime instead of using Loop's local-dev hardcoded URL:
   ```powershell
   $idx = 'index.html'
   $content = Get-Content $idx -Raw
   # Loop's build hardcodes their local dev URL (https://web-previewer.local.usercontent.microsoft.com:8135)
   # as __wp_script_base_url__. That string is also the absolute publicPath baked into chunk loader code in boot.js.
   # Replace the literal-string assignment with a runtime expression so chunk URLs resolve relative to
   # document.baseURI — works in BOTH:
   #   - local dev (SDX bundle at  https://fa000000194.resources.office.net/web-previewer/index.html)
   #   - prod/Dogfood (SDX bundle at  https://fa000000194.resources.office.net/<guid>/<version>/en-us_web/web-previewer/index.html)
   $pattern = "__wp_script_base_url__ = 'https://web-previewer.local.usercontent.microsoft.com:8135/?'"
   $replacement = "__wp_script_base_url__ = new URL('./', document.baseURI).href"
   ($content -replace $pattern, $replacement) | Set-Content $idx -Encoding UTF8 -NoNewline
   ```
   **Do NOT** replace the URL with `'https://fa000000194.resources.office.net/web-previewer/'` (a hardcoded
   absolute URL). The SDX deployment path includes a `<guid>/<version>/en-us_web/` prefix that the
   hardcoded URL skips, causing every chunk request to 400 in deployed environments. The 1JS midgard
   build assumes their local dev URL because that's where they test — we have to neutralize it.
