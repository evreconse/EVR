# SCORING.md

# EVRECONSE Scoring System Specification

**Document Version:** 1.0  
**Status:** Approved for MVP Foundation

---

# 1. Purpose

Данный документ описывает архитектуру системы оценки (Scoring Engine).

Scoring Engine предназначен для количественной оценки каждого найденного рыночного события.

Scoring Engine НЕ принимает торговых решений.

Он только вычисляет итоговую оценку события.

Решение об отправке уведомления принимается отдельным модулем.

---

# 2. Philosophy

Система оценки должна соответствовать следующим принципам:

- Объективность
- Повторяемость
- Объяснимость
- Конфигурируемость
- Расширяемость

Ни один параметр не должен быть жестко встроен в код.

---

# 3. General Formula

Каждое событие получает итоговую оценку.

```
Final Score = ?(Parameter Scores)
```

Максимальная оценка:

```
100
```

Минимальная:

```
0
```

---

# 4. MVP Parameters

Для первой версии используются только следующие параметры.

## Lower Wick Quality

Оценивает качество нижней тени свечи.

---

## Liquidation Strength

Оценивает силу ликвидаций.

---

## Candle Confirmation

Проверяет соответствие свечи условиям стратегии.

---

Все остальные параметры будут добавляться позднее.

---

# 5. Future Parameters

В будущем система должна поддерживать:

- Volume
- Open Interest
- Funding Rate
- Delta
- CVD
- ATR
- Spread
- Volatility
- Trend Context
- Time Session
- BTC Correlation

Поддержка данных параметров не входит в MVP.

---

# 6. Configuration

Все параметры должны храниться в конфигурации.

Запрещено использовать фиксированные значения внутри кода.

Пример:

```yaml
score:
  minimum_signal_score: 80
```

---

# 7. Explainability

После вычисления оценки система обязана сохранять вклад каждого параметра.

Пример:

```
Lower Wick ........ 40

Liquidation ....... 35

Confirmation ...... 20

Penalty ........... -5

TOTAL ............. 90
```

Это необходимо для анализа качества стратегии.

---

# 8. Signal Threshold

Scoring Engine не отправляет уведомления.

Он только вычисляет оценку.

Решение принимает Signal Engine.

Например:

```
Score >= 80

?

Send Telegram
```

Порог должен храниться только в конфигурации.

---

# 9. Statistics

Для каждого события сохраняются:

- Final Score
- Score Breakdown
- Timestamp
- Symbol
- Strategy
- Outcome (после завершения сделки)

---

# 10. Future Improvements

После накопления достаточной статистики допускается:

- изменение весов;
- добавление новых факторов;
- отключение факторов;
- автоматическая оптимизация весов.

Любое изменение должно быть подтверждено статистическим анализом.

---

# 11. Restrictions

Scoring Engine запрещено:

- принимать торговые решения;
- открывать сделки;
- отправлять сообщения;
- изменять данные рынка.

Scoring Engine является исключительно модулем оценки.

---

# 12. Definition of Done

Система оценки считается корректной, если:

- любой параметр можно включить или отключить;
- веса можно менять без изменения кода;
- итоговая оценка полностью объяснима;
- каждое событие сохраняет подробную структуру оценки;
- система поддерживает дальнейшее расширение.
