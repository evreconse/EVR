**Document Version:** 1.0

## 1. Назначение Configuration System

Configuration System — централизованный слой управления всеми настраиваемыми параметрами системы EVRECONSE.

Принцип **Configuration First** (CORE_SPECIFICATION.md) требует, чтобы все изменяемые параметры были вынесены в конфигурацию. Код системы не должен содержать значений, которые могут измениться при эксплуатации.

Configuration Manager (SYSTEM_ARCHITECTURE.md) — единственный поставщик конфигурации для всех модулей. Модули не имеют собственных настроек и не читают конфигурацию напрямую. Они получают параметры от Configuration Manager.

---

## 2. Категории конфигурации

Конфигурация разделяется на категории по источнику и чувствительности:

### 2.1 Категории по источнику

| Категория | Источник | Примеры |
|-----------|----------|---------|
| **Static Config** | Файлы конфигурации (configs/) | Параметры стратегий, пороги, списки инструментов |
| **Secrets** | Переменные окружения (.env) | API ключи, токены, chat ID |
| **Runtime Config** | Изменяется без перезапуска | Список инструментов (частично), порог Score |

### 2.2 Категории по модулю-потребителю

| Категория | Модуль | Описание |
|-----------|--------|----------|
| Exchange | Data Provider | Настройки подключения к бирже |
| Strategy | Strategy Engine | Параметры стратегий |
| Scoring | Scoring Engine | Параметры оценки |
| Notification | Notification Service | Настройки уведомлений |
| Risk | Outcome Tracker | TP/SL параметры |
| Storage | Storage Service | Настройки хранения |
| System | Все модули | Общие системные параметры |

## 4. Параметры, запрещённые к хранению в коде

Следующие типы параметров запрещено хранить непосредственно в исходном коде:

### 4.1 Зашитые числа (Magic Numbers)

- Пороговые значения (Score threshold, Wick ratio)
- Количественные константы (окно ликвидаций 12, максимальное количество инструментов 250)
- Проценты (TP 3%, SL 3%)
- Таймауты и задержки

**Источник требования:** CORE_SPECIFICATION.md — принцип No Magic Numbers.

### 4.2 Чувствительные данные (Secrets)

- API ключи биржи
- Секретные ключи
- Токены Telegram бота
- Chat ID
- Любые credentials

**Источник требования:** SYSTEM_ARCHITECTURE.md — Configuration Manager.

### 4.3 Идентификаторы и имена

- Названия бирж
- Тикеры инструментов
- Идентификаторы стратегий
- Список активных модулей

### 4.4 Флаги функциональности

- Какие стратегии активны
- Какие параметры скоринга включены
- Какие каналы уведомлений используются

**Исключение:** Значения, которые являются частью алгоритма и никогда не изменятся (например, математическая формула расчёта Lower Wick как High - Low или логика сравнения Score >= Threshold). Формулы и алгоритмы — это код, а не конфигурация.

## 5. Параметры, изменяемые без перезапуска

Следующие параметры могут быть изменены без остановки системы:

| Параметр | Обоснование |
|----------|-------------|
| score.minimum_signal_score | Изменение порога не требует перезапуска цепочки обработки |
| strategy.LW-001.enabled | Включение/отключение стратегии на лету |
| strategy.LW-001.condition.liquidation_window | Изменение окна расчёта применяется к следующей свече |
| score.parameters.*.enabled | Активация/деактивация параметров оценки |
| score.parameters.*.max_score | Изменение веса параметра |
| notification.channels | Подключение нового канала уведомлений |
| risk.monitoring.max_duration | Изменение лимита ожидания |
| system.log_level | Изменение уровня логирования |

**Механизм:** Configuration Manager периодически проверяет изменения конфигурационных файлов или получает сигнал о необходимости перезагрузки. Модули получают обновлённые параметры при следующем запросе.

## 6. Параметры, требующие перезапуска

Следующие параметры требуют перезапуска системы:

| Параметр | Причина |
|----------|---------|
| exchange.name | Смена биржи требует пересоздания WebSocket соединения |
| exchange.symbols | Добавление/удаление инструментов требует переподписки |
| exchange.timeframe | Смена таймфрейма меняет частоту событий |
| exchange.api_key / exchange.api_secret | Требуют новой аутентификации |
| notification.telegram.bot_token | Требует нового подключения к Telegram API |
| storage.data_path | Путь хранения фиксируется при инициализации |
| storage.events.retention_days | Требует пересмотра политики хранения |
| strategy.LW-001.condition.lower_wick_ratio | Хотя технически может быть hot-reload, для MVP — restart |
| system.timezone | Привязка временных меток |

**Принцип:** Параметры, влияющие на подключение к внешним сервисам, инициализацию модулей или структуру данных, требуют перезапуска. Параметры, влияющие только на логику обработки, могут быть изменены без перезапуска.

## 7. Правила валидации конфигурации

Configuration Manager должен проверять следующие аспекты при загрузке конфигурации:

### 7.1 Проверка типов

| Параметр | Ожидаемый тип | Пример невалидного значения |
|----------|---------------|----------------------------|
| score.minimum_signal_score | Number | "high" (String) |
| exchange.symbols | Array | null |
| exchange.timeframe | String, один из: M1, M5, M15, M30, H1 | M7 |
| exchange.api_key | String, не пустой | "" |
| notification.telegram.bot_token | String, не пустой | null |

### 7.2 Проверка диапазонов

| Параметр | Допустимый диапазон |
|----------|---------------------|
| score.minimum_signal_score | 0–100 |
| score.maximum_score | 0–100, > minimum_score |
| exchange.reconnect.max_delay | 10s–600s |
| risk.take_profit_percent | > 0 |
| risk.stop_loss_percent | < 0 |
| exchange.symbols.min | >= 1 |
| exchange.symbols.max | >= exchange.symbols.min |

### 7.3 Проверка зависимостей

- Если стратегия активна, её параметры должны быть заданы.
- Если Telegram указан в notification.channels, bot_token и chat_id должны быть непустыми.
- Если параметр скоринга активен, его max_score должен быть > 0.

## 8. Поведение при отсутствии обязательных параметров

### 8.1 Обязательные параметры

Следующие параметры являются обязательными. Без них система не может запуститься:

- exchange.api_key
- exchange.api_secret
- notification.telegram.bot_token
- notification.telegram.chat_id
- exchange.symbols (хотя бы один инструмент)

### 8.2 Действие при отсутствии

- Если отсутствует обязательный параметр — система НЕ запускается.
- Configuration Manager возвращает ошибку с указанием отсутствующего параметра.
- Startup прерывается до исправления конфигурации.
- Логируется сообщение: обязательный параметр <имя> не найден.

### 8.3 Действие при отсутствии необязательного параметра

- Если отсутствует необязательный параметр — используется значение по умолчанию.
- Логируется предупреждение: параметр <имя> не найден, используется значение по умолчанию <значение>.
- Система запускается без ошибки.

---

## 9. Поведение при некорректной конфигурации

### 9.1 При запуске

- Если тип параметра не соответствует ожидаемому — система НЕ запускается.
- Если значение вне допустимого диапазона — система НЕ запускается.
- Если нарушены зависимости параметров — система НЕ запускается.
- Configuration Manager возвращает полный список ошибок валидации (не останавливается на первой).

### 9.2 Во время работы (hot-reload)

- Если новый файл конфигурации содержит ошибки — изменения НЕ применяются.
- Система продолжает работать с предыдущей валидной конфигурацией.
- Логируется предупреждение: изменения конфигурации отклонены.
- Если конфигурация повреждена (например, файл удалён) — система продолжает работу с последней загруженной конфигурацией.

## 10. Возможность расширения конфигурации

### 10.1 Добавление новой стратегии

Новая стратегия добавляется в раздел strategy. Конфигурация стратегии содержит её ID, флаг активности, параметры условий, риск-параметры и настройки уведомлений.

Правила:
- Новый блок strategy.<ID> не требует изменения структуры конфигурации.
- Система игнорирует неактивные стратегии.
- Значения по умолчанию для стратегии определяются в документации стратегии.

### 10.2 Добавление новой биржи

Новый блок exchange в конфигурации выбирает биржу. Формат выходных данных Data Provider унифицирован.

Правила:
- Параметр exchange.name определяет, какую реализацию Data Provider использовать.
- Все реализации принимают одинаковую структуру конфигурации.
- Специфичные для биржи параметры добавляются в блок exchange.<name>.

### 10.3 Добавление нового канала уведомлений

Новый канал добавляется в notification.channels и notification.<channel>.

Правила:
- Notification Service читает список активных каналов из notification.channels.
- Для каждого канала — отдельный блок конфигурации.
- Добавление канала не требует изменения существующих блоков.

### 10.4 Добавление параметра оценки Scoring

Новый параметр добавляется в score.parameters.

Правила:
- Параметр включается через score.parameters.<name>.enabled.
- max_score определяет вес параметра в общей сумме.
- Сумма max_score всех активных параметров не должна превышать score.maximum_score.

## 11. Правила версионирования конфигурации

### 11.1 Версия схемы

Файл конфигурации содержит поле system.config_version, указывающее версию схемы конфигурации.

### 11.2 Мажорная версия

Увеличивается при:
- удалении параметра;
- переименовании параметра;
- изменении типа параметра;
- изменении правил валидации.

При смене мажорной версии старая конфигурация несовместима.

### 11.3 Минорная версия

Увеличивается при:
- добавлении нового необязательного параметра;
- изменении значения по умолчанию.

Минорные изменения обратно совместимы.

### 11.4 Обратная совместимость

- Система загружает конфигурацию той же мажорной версии.
- Если мажорная версия не совпадает — система НЕ запускается.
- Неизвестные параметры игнорируются.
- Отсутствующие необязательные параметры заполняются значениями по умолчанию.

## 12. Принципы безопасного хранения чувствительных данных

### 12.1 Разделение

- Чувствительные данные (Secrets) НЕ хранятся в файлах конфигурации.
- Secrets хранятся в переменных окружения (.env файл).
- .env файл исключён из системы контроля версий (.gitignore).

### 12.2 Доступ

- Secrets доступны только Configuration Manager.
- Configuration Manager предоставляет secrets модулям по запросу.
- Модули не имеют прямого доступа к .env или переменным окружения.

### 12.3 Логирование

- Secrets НЕ логируются.
- Если необходимо залогировать факт использования secrets, логируется только наличие (true/false), не значение.

### 12.4 Шаблон

- Шаблон .env.example содержит все необходимые переменные с пустыми значениями.
- .env.example включён в систему контроля версий.
- .env — нет.

### 12.5 Ротация

- Система поддерживает возможность перезапуска с новыми secrets без изменения файлов конфигурации.
- Изменение secrets требует перезапуска.

### A.1 Соответствие существующей архитектуре

| Критерий | Статус |

Противоречий не обнаружено.

### A.2 Найденные риски

| Риск | Описание | Степень |
|------|----------|---------|
| **Hot-reload границы** | Некоторые параметры, помеченные как restart-only (например, lower_wick_ratio), могут технически быть hot-reload, но в MVP решено требовать restart. Может вызвать неудобство при настройке. | Низкая |
| **Сумма max_score** | При добавлении новых параметров скоринга может потребоваться перераспределение max_score между активными параметрами, что может нарушить существующие расчёты. | Средняя |
| **Совместимость стратегий** | Разные стратегии могут иметь конфликтующие параметры (разные таймфреймы, разные инструменты). Конфигурация должна это учитывать. | Средняя |
| **Отсутствие механизма hot-reload** | Документация описывает, какие параметры могут изменяться без перезапуска, но не определяет механизм (файл, API, сигнал). Это потребует уточнения при реализации. | Средняя |

### A.3 Предложения по улучшению

| Улучшение | Обоснование |
|-----------|-------------|
| **Иерархия конфигурации с наследованием** | Общие параметры (TP/SL по умолчанию) могут быть переопределены на уровне стратегии. Уменьшит дублирование. |
| **Валидация ссылок между параметрами** | Например, strategy.LW-001.timeframe должен совпадать с exchange.timeframe или быть его множителем. |
| **Graceful degradation при ошибке hot-reload** | Чётко определить, что система продолжает работу со старой конфигурацией при ошибке загрузки новой. |
| **Аудит изменений конфигурации** | Логировать все изменения конфигурации (кто, когда, что изменил). |

### A.4 Уровень уверенности

**Высокий.** Документ полностью основан на утверждённой документации. Все параметры имеют явные источники в спецификациях. Категоризация и правила соответствуют архитектурным принципам проекта. Основной риск — отсутствие механизма hot-reload, но это не противоречие, а открытый вопрос для реализации.
